## Project Overview

MicroPython weather display for Raspberry Pi Pico 2 W with a Waveshare 3.7" e-paper display (480×280 px, EPD_3IN7). The device shows time, weather, and a calendar. It runs a web-based configuration UI over WiFi.

**Hardware target:** Raspberry Pi Pico 2 W + Waveshare 3.7" e-paper, powered by three 3450 mAh 18650 cells in parallel (3P, 3.7 V nominal, 10350 mAh).

## Deploying to the Device

There is no build step. Files are transferred directly to the Pico using the **MicroPico** VSCode extension (identifier: `paulober.pico-w-go`).

- Upload a file: right-click in VSCode → "Upload file to Pico"
- Upload entire project: right-click project root → "Upload project to Pico"
- Run on device: use the MicroPico Run button or REPL

The `.micropico` file marks the project root for the extension. MicroPython stubs live at `~/.micropico-stubs/included` and are referenced in `.vscode/settings.json` for Pylance type checking.

## Architecture

### Main Application (`main.py`)

Three manager classes handle configuration, networking, and web UI:

- **`ConfigManager`** — loads/saves `config.json` on the Pico filesystem. Sections: `wifi` (ssid, password), `time` (is_24h, week_start), `weather` (api_key, city coords, is_celsius).
- **`WiFiManager`** — switches between AP mode (SSID `ePaper`, password `paper1234`, IP `192.168.4.1`, hard-coded by the rp2 CYW43 firmware) for initial setup and STA mode for normal operation (15 s timeout).
- **`WebConfigServer`** — HTTP server on port 80; handles GET/POST for settings, serves city list from `taiwan_cities.json`, exposes `weather.log` for download.

Display functions are module-level:
- `show_wifi_guide()` / `show_message()` — setup and status screens
- `ntp_sync()` — syncs via `time.apple.com`, 30 s timeout
- `fetch_weather()` — calls OpenWeatherMap `data/2.5/weather` with 3 retries / 5 s gap / 60 s timeout; appends result to `weather.log`
- `draw_calendar()` — full monthly calendar view
- `draw_main_screen()` — composite view: current time, weather, mini-calendar

**Main loop** (bottom of `main.py`): checks for WiFi config → falls back to AP setup or connects STA → NTP sync → draw calendar → fetch weather → draw main screen → minute-tick partial refresh; full weather refresh at 11:00 and 23:00; NTP re-sync at 23:59.

### E-Paper Driver (`Pico_ePaper_3_7.py`)

Subclasses `framebuf.FrameBuffer`. Key details:

- SPI pins: RST=12, DC=8, CS=9, BUSY=13; baudrate 4 MHz
- Two display modes: 4-grayscale (`EPD_3IN7_4Gray_init` / `EPD_3IN7_4Gray_Display`) and 1-bit black/white (`EPD_3IN7_1Gray_init` / `EPD_3IN7_1Gray_Display`)
- Partial refresh (`EPD_3IN7_1Gray_Display_Part`) is black/white only — used for the clock tick to avoid full refresh flicker
- `Sleep()` puts the panel in deep power-save mode

### Writer / Font System (`writer/`)

`writer.py` provides `Writer` (monochrome) and `CWriter` (colour) classes that render pre-generated Python font files onto any `framebuf` device. Per-device state is tracked by device ID.

Font files (`freesans20.py`, `courier20.py`, `font10.py`, `font6.py`) are generated by the `font-to-py` utility and each export `height()`, `max_width()`, `get_ch()`, and metadata functions.

### External Data

- `taiwan_cities.json` — 22 Taiwan cities with lat/lon, served by `WebConfigServer` for city selection
- `API/OpenWeather/` — Bruno API client collection for testing OpenWeatherMap endpoints (current weather, geocoding) during development

## Key Runtime Files (on-device filesystem)

| File | Purpose |
|---|---|
| `config.json` | Persisted settings (WiFi, time, weather) |
| `weather.log` | Append-only API call log; cleared monthly on the 1st |

## Display Coordinates

The physical panel is 480 px wide × 280 px tall (landscape). The driver applies a 90° rotation internally; draw calls use `(x, y)` in the rotated coordinate space.
