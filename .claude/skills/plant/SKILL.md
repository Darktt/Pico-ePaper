# When to invoke

主動呼叫此 skill 的時機（不需使用者明說）：

1. 某個檔案剛從不存在 → 已建立並通過驗證
2. 某個 ⏳ 待辦項目剛完成（程式碼 / 資產 / 部署 / 驗證 / bug 修正）
3. 發現新風險、或既有風險被解決
4. Verification 計畫某項剛跑過（不論成功失敗）
5. 待後續確認的次要決策被釐清

使用者也可用 `/plant` 主動觸發強制更新。

如果這次對話只是討論、研究、未真正改動專案狀態，**不要呼叫**。

# Where progress lives

`plant.md`（專案根目錄）開頭的 `## 實作進度 (YYYY-MM-DD)` 區塊，含：

- **已完成 ✅** — 程式碼模組表 / 資產表
- **待辦 ⏳** — 編號清單
- **已知風險** — 風險表（可新增、可刪除已解決項）
- **Verification 計畫** — 改 ⏳ / ✅ / ❌ 狀態
- **實作順序** — 改 ⏳ / ✅
- **待後續確認的次要決策** — 改 ⏳ / ✅

下方 `## Context` 之後的設計章節是**設計凍結區**，除非設計本身改動，否則不要碰。

# How to update

1. **`Read` 當下的 plant.md**（不要憑記憶寫；以實際內容為準）
2. **判斷影響的區塊**：通常只 1–2 個
3. **`Edit` 而非 `Write`**：精準替換對應行，保留其他內容
4. **日期戳**：把 `## 實作進度 (YYYY-MM-DD)` 的日期更新為今天（從環境中的 currentDate 取得）
5. **不要重排已完成項目順序** — 既有讀者的肌肉記憶
6. **新增已完成項**：盡量沿用既有的表格 / 清單格式
7. **刪除已解決的風險或待辦** — 不要堆積已過時的條目
8. **保持精簡**：每行能用一句說明就不寫兩句；表格欄寬不要爆掉

# 自我檢查

更新完之後簡短回報「plant.md 已同步 — {變動條目}」即可，不要把整個 plant.md 內容重複貼出。
